# FIFO Verification (SystemVerilog)

Пет-проект: верификация синхронного FIFO на SystemVerilog.

## Что это

FIFO (First In, First Out) — буфер, в котором данные читаются в том же порядке, в котором были записаны. Используется для сглаживания разницы скоростей между блоками в цифровых схемах.

## Структура проекта

- `rtl/fifo.sv` — RTL-модуль параметризуемого синхронного FIFO.
- `tb/tb_top.sv` — тестбенч: генерация стимулов, скорборд, функциональное покрытие.
- `README.md` — описание проекта.

## RTL: что делает FIFO

- Параметры: `DATA_WIDTH` (ширина слова), `DEPTH` (глубина, степень двойки).
- Внутри: массив памяти `mem`, указатели `wr_ptr` и `rd_ptr`, счётчик `count`.
- Флаги `full` (счётчик == DEPTH) и `empty` (счётчик == 0).
- Логика записи/чтения через `case` по комбинации `{wr_en & ~full, rd_en & ~empty}`:
  - `2'b10` — только запись;
  - `2'b01` — только чтение;
  - `2'b11` — запись и чтение одновременно (count не меняется);
  - `2'b00` — ничего (idle).

## Архитектура тестбенча

Стимулы → DUT → Скорборд → Отчёт
↓
Покрытие

- **Стимулы**: `wr_en`, `rd_en`, `data_in` генерируются случайно через `$urandom`.
- **Скорборд**: эталонная очередь `model [$]`. При чтении достаём из очереди и сравниваем с `data_out`. При записи кладём `data_in` в очередь.
- **Покрытие**: ручной сбор по `wr_en`, `rd_en`, `full`, `empty` и их крестам.

## Сценарии теста

1. **Случайный стимул** — 500 тактов со случайными `wr_en`/`rd_en`/`data_in`.
2. **Directed: fill to full** — заполнить FIFO до флага `full`, проверить, что данные не перезаписываются.
3. **Directed: drain to empty** — опустошить FIFO до флага `empty`, проверить, что данные не портятся.

## Результат

[COV] wr_en: 0=261, 1=281
[COV] rd_en: 0=294, 1=248
[COV] full: 0=477, 1=65
[COV] empty: 0=526, 1=16
[COV] wr/rd: 00=130, 01=131, 10=164, 11=117

- 237 проверок, 0 ошибок, `TEST PASSED`.
- Покрытие: все комбинации `wr_en`, `rd_en`, `full`, `empty` протестированы.

## Найденный баг

В RTL был специально внесён баг — убрана защита `& ~full` в условии записи:

// Было (правильно):
case ({wr_en & ~full, rd_en & ~empty})

// Стало (баг):
case ({wr_en, rd_en & ~empty})

FIFO начал писать, когда полон → данные перезаписывались → скорборд выдал:

text
[SCB] MISMATCH: expected=0xf2 actual=0x1c
TEST FAILED

После возврата & ~full — снова TEST PASSED. Это доказывает, что тест реально проверяет поведение DUT, а не формально проходит.
